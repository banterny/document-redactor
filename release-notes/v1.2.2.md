# document-redactor v1.2.2

_Released 2026-07-29_

A correctness and reliability release. **If you use this tool in Safari, or on an
iPhone or iPad, you should update.** Detection results are unchanged.

## What's fixed

- **The tool could freeze for seconds — or minutes — on Safari and on every
  browser on iOS or iPadOS.** Thirteen detection rules backtracked
  catastrophically on ordinary document shapes: long runs of spaces, digits or
  hyphens, of the kind produced by column-aligned tables, padded forms and
  discharge summaries. Detection runs on the main thread, so an affected
  document locked the tab until Safari's own 30-second script timeout killed
  it. Two of the rules were bad enough to breach their budget at around 150
  consecutive spaces.

  Chrome, Edge and Firefox were **not** affected, which is why this went
  unnoticed: the same rules measured 0.00ms there. The cause is a difference
  between JavaScript engines — Safari and iOS use JavaScriptCore, which does
  not apply an optimisation that hides the cost on the others.

- Measured in Safari 26 on the two worst rules, at 10,000 characters of
  adversarial input: 699.6ms → 12.0ms, and 79.1ms → 2.9ms. One rule went from
  quadratic to linear growth, so the improvement widens as documents get
  larger.

## Does this change what gets redacted?

**Almost entirely no, and the exception is deliberate.** Every pattern change
was differential-tested against the previous pattern before it landed — over
190,000 label, separator, padding and value combinations, with zero
differences on all but one rule.

The single exception is the Korean corporate-suffix rule (`X 주식회사`): a
company name longer than 256 characters that sits immediately after `&`, `.` or
`-` is no longer matched. That boundary was located by binary search rather
than estimated, is pinned by tests on both sides, and no real company name
approaches it. It is documented in the source.

## Also in this release

- The in-app footer now reports `v1.2.2`.
- The ReDoS test gate benchmarks every rule under **both** JavaScript engines
  rather than one, so this class of defect cannot recur unseen. It also now
  measures CPU time rather than wall-clock, which removes a long-standing
  source of spurious test failures.
- The single-file HTML build is about **278 KB** and still makes zero network
  requests.

## Verify your download

Save both files to the same directory and run:

```bash
sha256sum -c document-redactor.html.sha256
# expected output:
#   document-redactor.html: OK
```

The sidecar is generated by the same build that produces the HTML, so the two
always correspond. Unlike previous releases, no hash is reproduced here by
hand: the build is byte-reproducible on a given platform, but that was not
verified across platforms, and a hash printed from a different machine to the
one that built the release would be worse than no hash at all.

## Known limitations

- This is still a deterministic local pre-upload filter, not a legal judgment
  engine.
- The tool does not decide whether a legal reference is sensitive in your
  specific matter; review the candidate list before applying redaction.
- DOCX output is verified after rewrite, but unsupported package structures may
  still need manual handling.
- Two rules carry documented, test-pinned detection limits at extreme input
  sizes: the UK legal-label scanner stops bridging a label to its value beyond
  roughly 100–165 consecutive whitespace characters, and the Korean corporate
  suffix rule has the 256-character limit described above. Neither shape occurs
  in real documents.
